# AI smells — patterns found in AI-generated code
# Source: synthetic
# Used by: principles-auditor
# Universal reference, independent of the stack.
---

These patterns describe defects that recur in code generated by, or heavily
assisted by, an AI. Examples specific to a language or framework belong in the
optional playbooks.

## 1. Over-generation

**Description:** Code, helpers, abstractions or layers created with no real need.
**Signs:** Unused functions, wrappers that only delegate, options that are never read.
**Fix:** Delete the code confirmed unused, or inline the trivial helpers.

## 2. Structural clones

**Description:** The same logical structure copied into several places.
**Signs:** Repeated validation → transformation → save sequences.
**Fix:** Extract only when the concept really is shared.

## 3. God modules

**Description:** One file concentrates several responsibilities.
**Signs:** Many imports, heterogeneous exports, high complexity, high churn.
**Fix:** Separate orchestration, domain, I/O and presentation.

## 4. Swallowed errors

**Description:** Errors caught, ignored or replaced by a neutral value.
**Signs:** Empty catch, critical result ignored, silent fallback.
**Fix:** Propagate, map, or handle explicitly.

## 5. Magic values

**Description:** Business numbers or strings with no name.
**Signs:** Hardcoded thresholds, delays, statuses or keys with no constant.
**Fix:** Extract a named constant close to its use.

## 6. Dual source of truth

**Description:** The same information maintained in several places.
**Signs:** Cache, derived state or config duplicated with no invalidation rule.
**Fix:** Pick one authoritative source and derive the rest.

## 7. Speculative state drift

**Description:** Local state modified before durable confirmation, with no rollback.
**Signs:** Optimistic write, or cache updated with no reconciliation.
**Fix:** Confirm, roll back, or reload from the authoritative source.

## 8. Stale context capture

**Description:** A callback, closure or async job uses stale context.
**Signs:** A value captured before a change of config, session or state.
**Fix:** Pass the needed values explicitly, or re-evaluate at the moment of acting.

## 9. Direct shared-state mutation

**Description:** Mutation of a shared object, bypassing its owner.
**Signs:** In-place modification of a structure used by several consumers.
**Fix:** Centralise the mutation and preserve the invariants.

## 10. Lifecycle dependency drift

**Description:** Initialisation, refresh or teardown depends on an implicit order.
**Signs:** A resource created with no clear update or destruction path.
**Fix:** Make the lifecycle explicit and tested.

## 11. Unvalidated external data

**Description:** External data used as trusted internal data.
**Signs:** Direct parsing, no validation, implicit format assumptions.
**Fix:** Validate and normalise at the boundary.

## 12. Type or contract escape hatch

**Description:** Bypassing the contract system of the language.
**Signs:** Broad cast, dynamic escape hatch, warning suppressed without justification.
**Fix:** Narrowing, validation, or an explicit domain type.

## 13. Missing cleanup

**Description:** A resource opened with no clear release.
**Signs:** Listener, timer, file, connection, transaction or lock with no cleanup.
**Fix:** Add teardown, scope management, or the finally/defer equivalent.

## 14. Pass-through plumbing

**Description:** Parameters threaded through several layers with no added value.
**Signs:** Call chains that only relay the same arguments.
**Fix:** Revisit the boundary, or bring the consumer closer to the source.

## 15. Export surface explosion

**Description:** Too many items exposed as public API.
**Signs:** Global exports, massive re-exports, modules with no clear boundary.
**Fix:** Expose only the intentional API.

## 16. Premature abstraction

**Description:** Interfaces, factories or abstract bases before several real usages.
**Signs:** A single implementation, no benefit from substitution.
**Fix:** Go back to the concrete until the need is proven.

## 17. Error type erasure

**Description:** Rich errors converted into generic messages.
**Signs:** Loss of cause, code, context or corrective action.
**Fix:** Preserve the cause and map it to a domain error.

## 18. Unit doing too much

**Description:** One function, class or module orchestrates too many phases.
**Signs:** Reading, validation, transformation, persistence and rendering together.
**Fix:** Extract the phases and name the responsibilities.

## 19. Stringly-typed protocols

**Description:** Internal protocols based on free-form strings.
**Signs:** Event, command or status names repeated with no contract.
**Fix:** Centralise the constants, or introduce a type/enum/schema.

## 20. Async without failure policy

**Description:** An asynchronous operation with no failure strategy.
**Signs:** No timeout, retry, propagation, cancellation or explicit fallback.
**Fix:** Define the error and duration policy.

## 21. Redundant derived data

**Description:** A derived value stored and synchronised by hand.
**Signs:** Totals, filtered lists or statuses that are recomputable, persisted locally.
**Fix:** Compute on demand, or document the invalidation.

## 22. Assertion on external data

**Description:** The code asserts an external format instead of checking it.
**Signs:** Permissive cast/deserialise with no domain validation.
**Fix:** Parse strictly at the boundary.

## 23. Missing loading, empty or error states

**Description:** Only the happy path is represented.
**Signs:** No behaviour for empty, error, timeout or permission denied.
**Fix:** Handle the states the workflow actually expects.

## 24. Hidden side effects

**Description:** A side effect inside a function that looks pure.
**Signs:** A read or formatting name that writes, hits the network, logs or mutates a global.
**Fix:** Separate it, or rename it explicitly.

## 25. Overly generic naming

**Description:** Vague names in non-trivial code.
**Signs:** `data`, `result`, `handler`, `manager`, `process`, `doStuff`.
**Fix:** Name after the domain and the real action.

## 26. Debug artifact proliferation

**Description:** Debug traces left in the final code.
**Signs:** Temporary logs, prints, dumps, TODOs with no owner.
**Fix:** Delete them, or replace them with justified structured instrumentation.

## 27. Missing public contract documentation

**Description:** A public API with no readable contract.
**Signs:** Public exports, commands, endpoints or modules with no description of inputs/outputs/errors.
**Fix:** Document them in the idiomatic format of the language.
